- 应用名称：简单测试时间
- 应用场景：只有一个页面，一个后端接口，页面上显示接口返回的后端系统时间。
- 目标终端：PC
- 导航布局：布局=side, 页头=启用, 页脚=禁用
- 主题色：#6b3cf0
- 数据源类型：database
- 认证：不启用
- 权限控制：不启用

### 需求规格

> 「简单测试时间」是一个面向 PC 端的极简演示应用，采用侧边导航布局、启用页头、禁用页脚，数据源类型为数据库。应用仅包含一个首页，页面通过调用唯一的一个后端接口获取并展示后端系统当前时间，用于验证前后端接口连通性与时间获取能力。应用不启用登录认证，也不涉及权限控制。

**用户角色**：
- 普通用户：访问应用首页并查看后端系统时间的终端使用者，无需登录即可使用。

**功能模块**：
- 系统时间展示（must）：通过后端接口获取后端系统当前时间并在首页展示，包含页面加载时获取时间与手动刷新时间的能力。

### 产品计划

**页面**：
- **系统时间展示页**（system_time_view，路径：/page/system-time-view）
  - 描述：应用首页。页面加载后调用后端时间接口，将返回的后端系统时间以清晰的文本形式展示给用户，并提供手动刷新按钮以重新获取最新时间；接口异常时提示获取失败。
  - 目标：让用户打开应用后即可看到后端系统当前时间，并可通过刷新操作重新获取最新时间，用于验证前后端接口连通性。

**业务流程**：
- 查看后端系统时间
  - 用户打开应用首页，前端调用后端时间接口获取后端系统当前时间并展示，用户可手动刷新重新获取。
  - 步骤：用户打开应用，进入系统时间展示页
  - 步骤：页面自动调用后端时间接口发起时间查询请求
  - 步骤：后端接口返回后端系统当前时间
  - 步骤：页面将返回的时间以文本形式展示给用户
  - 步骤：用户点击刷新按钮，页面重新调用接口并更新展示的时间
  - 步骤：若接口调用失败，页面提示时间获取失败并允许用户重试

### 技术计划

- 前端架构：基于单页应用生成页面、路由和 API 客户端。
- 后端架构：后端技术栈固定为 Java8 + Springboot，提供真实 HTTP API、资源接口和业务契约实现。
- 数据层：数据库固定使用 MySQL8，缓存固定使用 Redis。

**实体**：
- **后端系统时间**（system_time）
  - 描述：由后端系统提供的当前时间信息，用于在页面展示后端系统当前时间。
  - 当前时间（current_time）：datetime，必填

### 接口设计

- **获取后端系统当前时间**
  - GET /api/system-time/current
  - 契约 `system_time_contract`，端点 `system_time_contract.get_current_time`
  - 描述：读取后端系统当前时间，返回精确到秒的当前时间，用于页面展示与刷新重试。
