## 分支 v1_0（2026-11-24 09:34:25 UTC）

**变更说明**：Z000000-0000 #comment chore: 新增人员明细列表首页，支持分页查看人员明细信息，并完成前后端数据对接。

### 应用现状

- 应用名称：人员明细
- 应用场景：人员明细列表页，所有人都可查看人员的明细列表，不能删改查人员信息；
- 目标终端：PC
- 导航布局：布局=side, 页头=启用, 页脚=禁用
- 主题色：#6b3cf0
- 数据源类型：database
- 认证：不启用
- 权限控制：不启用

### 需求规格

> 「人员明细」是一款面向 PC 端的人员明细信息查看应用。应用以侧边导航布局呈现（页头启用、页脚禁用），提供人员明细列表页，任何使用者均可查看人员的基本明细信息，但不得新增、删除或修改人员信息。列表采用普通分页方式展示数据，数据来源于数据库，应用不启用登录认证，也不涉及权限控制。

**用户角色**：
- 人员信息查看者：查看人员明细列表及人员基本明细信息的业务参与者，仅具备查看能力，不得删除、修改或查询检索以外的变更人员信息操作。

**功能模块**：
- 人员明细管理（must）：承载人员明细信息的展示能力。维护人员明细列表的展示，包括人员基本明细信息的呈现。仅支持查看操作，不提供新增、删除、修改人员信息的能力。列表采用普通分页方式逐页浏览，不提供额外的检索、筛选或导出能力。该只读约束对本应用所有涉及人员明细的页面统一生效。

### 产品计划

**页面**：
- **人员明细列表**（personnel_detail_list，路径：/page/pers-detail）
  - 描述：人员明细列表页为本应用首页，位于启用页头的侧边导航布局中。页面以表格形式展示人员的明细信息，支持以普通分页方式逐页浏览人员数据。所有使用者均可查看人员明细列表，页面不提供人员信息的新增、删除、修改入口，也不提供除分页浏览外的其他数据处理操作。
  - 目标：让所有使用者在一个只读列表中按普通分页方式逐页查看人员的明细信息，且不出现任何新增、删除、修改人员信息的入口。

**业务流程**：
- 人员明细查看流程
  - 使用者浏览人员明细信息的只读流程，贯穿列表页，遵循人员明细管理模块的只读约束。
  - 步骤：使用者进入人员明细应用，通过侧边导航进入人员明细列表页
  - 步骤：系统以表格形式展示人员的明细信息，并按普通分页方式分页呈现
  - 步骤：使用者通过分页控件切换页面，逐页查看人员明细信息
  - 步骤：使用者查看人员明细信息，系统不提供新增、删除或修改人员信息的操作入口

### UI 设计稿

- personnel_detail_list

### 技术计划

- 前端架构：基于单页应用生成页面、路由和 API 客户端。
- 后端架构：后端技术栈固定为 Java8 + Springboot，提供真实 HTTP API、资源接口和业务契约实现。
- 数据层：数据库固定使用 MySQL8，缓存固定使用 Redis。

**实体**：
- **人员明细**（personnel_detail）
  - 描述：记录人员的基本明细信息，用于在只读列表中分页查看。
  - 姓名（唯一标识）（name）：text，必填
  - 性别（gender）：enum，选填
  - 年龄（age）：number，选填
  - 联系电话（phone）：text，选填
  - 电子邮箱（email）：text，选填
  - 所属部门（department）：text，选填
  - 职位（position）：text，选填
  - 入职日期（entry_date）：date，选填
  - 备注（remark）：long_text，选填

### 接口设计

- **分页查询人员明细**
  - GET /personnel-details
  - 契约 `personnel_detail_contract`，端点 `personnel_detail_contract.listPersonnelDetails`
  - 描述：分页查询人员明细列表，支持按页码和每页条数浏览；返回人员姓名、性别、年龄、电子邮箱、所属部门、职位、入职日期和备注等明细信息。列表分页。

### 数据源

- **studio**（类型：database）

### 接口设计

- **分页查询人员明细**
  - GET /personnel-details
  - 契约 `personnel_detail_contract`，端点 `personnel_detail_contract.listPersonnelDetails`
  - 描述：分页查询人员明细列表，支持按页码和每页条数浏览；返回姓名、性别、年龄、联系电话、座机号、电子邮箱、所属部门、职位、入职日期和备注等明细信息。列表分页。

### 数据源

- **studio**（类型：database）
