## 分支 v1_0（2026-11-20 03:27:55 UTC）

**变更说明**：Z000000-0000 #comment chore: 新增欢迎页，页面加载后从后端获取问候语并展示在主体区域。

### 应用现状

- 应用名称：欢迎页
- 应用场景：开发一个前端页面，页面上一个接口返回字符串“早上好！”，前端展示这个字符串
- 目标终端：PC
- 导航布局：布局=side, 页头=启用, 页脚=禁用
- 主题色：#6b3cf0
- 数据源类型：database
- 认证：不启用
- 权限控制：不启用

### 需求规格

> 一个面向 PC 终端的前端展示应用，通过接口获取后端返回的字符串「早上好！」，并在页面上展示该字符串。应用采用侧边导航布局，启用页头、禁用页脚，数据来源于数据库，不启用登录认证，也不涉及权限控制。

**用户角色**：
- 使用人员：访问应用并查看接口返回问候语的普通使用人员。

**功能模块**：
- 问候展示（must）：调用后端接口获取问候字符串并展示在页面上。

### 产品计划

**页面**：
- **欢迎页**（home，路径：/page/home）
  - 描述：首页展示后端接口返回的字符串「早上好！」，接口加载完成后在页面主体区域呈现该问候语。
  - 目标：让使用人员打开应用后，在页面主体区域直接看到接口返回的问候语「早上好！」，无需任何额外操作即可确认应用运行正常。

**业务流程**：
- 查看欢迎问候
  - 使用人员打开应用首页，前端调用接口获取问候字符串并展示。
  - 步骤：使用人员打开应用首页
  - 步骤：前端请求后端问候接口
  - 步骤：接口返回字符串「早上好！」
  - 步骤：前端在页面主体区域展示该字符串

### UI 设计稿

- home

### 技术计划

- 前端架构：基于单页应用生成页面、路由和 API 客户端。
- 后端架构：后端技术栈固定为 Java8 + Springboot，提供真实 HTTP API、资源接口和业务契约实现。
- 数据层：数据库固定使用 MySQL8，缓存固定使用 Redis。

**实体**：
- **问候语**（greeting）
  - 描述：应用向前端返回并展示的问候字符串，核心内容为「早上好！」，由后端接口统一提供。
  - 问候语内容（content）：text，必填

### 接口设计

- **获取问候语**
  - GET /api/greetings
  - 契约 `greeting_contract`，端点 `greeting_contract.getGreeting`
  - 描述：返回应用展示的问候字符串，当前内容为「早上好！」，供欢迎页主体区域展示，无需任何请求参数即可读取。

## 分支 v1_2（2026-11-20 07:40:35 UTC）

**变更说明**：Z000000-0000 #comment chore: 本次上线门禁卡管理功能：新增系统主页及门禁卡领用、退还、注销完成等页面，员工可查看名下待领签与使用中的门禁卡，完成领签签收并提交离职注销申请，注销完成后展示实体卡交接的管理员信息。

### 应用现状

- 应用名称：欢迎页
- 应用场景：开发一个前端页面，页面上一个接口返回字符串“早上好！”，前端展示这个字符串
- 目标终端：PC
- 导航布局：布局=side, 页头=启用, 页脚=禁用
- 主题色：#6b3cf0
- 数据源类型：database
- 认证：不启用
- 权限控制：不启用

### 需求规格

> 面向成都中心门禁卡管理的移动端（招乎APP扫码进入MP小程序）应用，同时在PC端保留问候展示能力。员工通过扫码识别本人身份，在移动端查看本人名下待领签的门禁卡申请明细并完成领用签收，查看本人名下使用中的门禁卡并发起离职注销申请，提交后进入已完成确认界面并被告知需线下交还实体卡；出差卡借用/归还仅作占位按钮。签收状态、注销申请等数据实时同步至飞码端门禁卡管理系统，审批与流程发起由飞码端完成，小程序不涉及管理权限。应用整体采用简洁扁平化的蓝色调风格。

**用户角色**：
- 全体员工：全体成都中心员工，通过招乎APP扫描二维码进入MP小程序，办理本人名下门禁卡的领用签收与离职注销申请，并查看本人名下的门禁卡数据。
- 综合事务室管理员：成都中心综合事务室负责场地运营方向的管理员，负责门禁卡管理的线下工作，包括回收员工线下交还的实体门禁卡。

**功能模块**：
- 问候展示（must）：调用后端接口获取问候字符串并展示在页面上。
- 门禁卡管理（must）：提供门禁卡领用签收、离职注销申请、已完成注销确认以及出差卡借用/归还（占位）等移动端操作入口与功能。

### 产品计划

**页面**：
- **欢迎页**（home，路径：/page/home）
  - 描述：首页展示后端接口返回的字符串「早上好！」，接口加载完成后在页面主体区域呈现该问候语。
  - 目标：让使用人员打开应用后，在页面主体区域直接看到接口返回的问候语「早上好！」，无需任何额外操作即可确认应用运行正常。
- **门禁卡管理主页面**（access_card_main，路径：/page/access_card/main）
  - 描述：小程序首页与功能入口，用户扫码进入后首先展示。顶部居中显示标题「成都中心门禁卡管理系统」，中部纵向排列四个矩形功能按钮：门禁卡领用、门禁卡归还、出差卡借用、出差卡归还（后两个为占位按钮，展示禁用标识、暂不提供实际功能），底部边缘展示高楼大厦、柱状图等装饰图形。整体蓝色调、简洁扁平化。
  - 目标：作为扫码进入后的首页与功能入口，让员工一眼看清可用的门禁卡功能，并能一键进入领用签收或归还注销流程。
- **门禁卡领用页面**（card_claim，路径：/page/access_card/claim）
  - 描述：员工查看本人名下待领签的门禁卡申请明细并完成领用签收。页面自上而下为标题「门禁卡领用」、说明文案「所有字段信息直接从扫码获取，并实时同步到飞码」、可翻页的申请明细列表（字段：姓名、员工编号、卡号、领签状态）、操作区（【完成领签】按钮、【返回首页】按钮）及底部功能图标区；支持单条勾选与一键全选，仅展示本人名下【待领签】的明细。
  - 目标：让员工在手机上核对自己名下待领签的门禁卡申请明细，通过勾选并完成领签，一步完成签收并让状态同步回飞码。
- **门禁卡归还页面**（card_return，路径：/page/access_card/return）
  - 描述：员工查看本人名下状态为「使用中」的门禁卡并发起离职注销申请（页面标题为「门禁卡退还」）。页面自上而下为标题区、说明文案「所有字段信息直接从扫码获取，并实时同步到飞码」、可翻页的门禁卡信息列表（字段：姓名、员工编号、卡号、权限状态）、操作区（【离职注销】按钮、【返回首页】按钮）及底部功能图标区；点击【离职注销】后跳转至已完成界面。
  - 目标：让员工核对自己名下使用中的门禁卡，一键发起离职注销申请，并在申请提交后获得后续线下交卡的明确指引。
- **已完成界面**（cancel_completed，路径：/page/access_card/cancel_completed）
  - 描述：离职注销申请提交成功后的确认提示页。居中展示标题「您已完成注销申请！」与说明文案「请把实体卡交给门禁卡管理员」，列出门禁卡管理员信息（园区：李媛/WS04462；OCG：徐敏/IT006877），并提供蓝色背景的【返回首页】按钮及底部功能图标区。
  - 目标：明确告知员工注销申请已提交成功，并指引其将实体卡线下交还给对应区域的门禁卡管理员。

**业务流程**：
- 查看欢迎问候
  - 使用人员打开应用首页，前端调用接口获取问候字符串并展示。
  - 步骤：使用人员打开应用首页
  - 步骤：前端请求后端问候接口
  - 步骤：接口返回字符串「早上好！」
  - 步骤：前端在页面主体区域展示该字符串
- 门禁卡领用签收
  - 员工通过招乎APP扫码进入小程序，查看本人名下待签收的门禁卡申请明细并完成领用签收，签收状态实时回传飞码。
  - 步骤：员工使用招乎APP扫描二维码进入小程序
  - 步骤：MP识别扫码人ID
  - 步骤：通过扫码ID与领签人匹配，识别本人名下【待签收】的申请数据明细
  - 步骤：手机端在门禁卡领用页面展示明细列表
  - 步骤：员工单条勾选或一键全选待领签明细
  - 步骤：点击【完成领签】，回填每条申请的【领签状态】为【已领签】
  - 步骤：签收状态数据传回飞码
- 离职注销申请
  - 员工查看本人名下使用中的门禁卡并发起离职注销申请，数据回传飞码触发注销流程，随后进入已完成界面获得线下交卡提示。
  - 步骤：员工使用招乎APP扫描二维码进入小程序
  - 步骤：识别扫码人ID，筛选本人名下【权限状态】为【使用中】的卡片信息展示
  - 步骤：点击【离职注销】按钮
  - 步骤：将【申请注销】字段更新为“离职”
  - 步骤：数据传回飞码，并在飞码发起现有注销流程
  - 步骤：进入已完成界面，提示员工线下将实体卡交还门禁卡管理员

### 技术计划

- 前端架构：基于单页应用生成页面、路由和 API 客户端。
- 后端架构：后端技术栈固定为 Java8 + Springboot，提供真实 HTTP API、资源接口和业务契约实现。
- 数据层：数据库固定使用 MySQL8，缓存固定使用 Redis。

**实体**：
- **问候语**（greeting）
  - 描述：应用向前端返回并展示的问候字符串，核心内容为「早上好！」，由后端接口统一提供。
  - 问候语内容（content）：text，必填
- **门禁卡申请明细**（access_card_application）
  - 描述：员工名下的一条门禁卡领用申请明细，包含姓名、员工编号、卡号、领签状态以及领签人身份标识（扫码人ID），领签状态在待领签与已领签之间流转。
  - 姓名（name）：text，必填
  - 员工编号（employee_no）：text，必填
  - 卡号（card_no）：text，必填
  - 领签状态（claim_status）：enum，必填
  - 领签人身份标识（claimer_id）：text，必填
- **门禁卡**（access_card）
  - 描述：员工名下的一张门禁卡信息，包含姓名、员工编号、卡号、权限状态和申请注销字段；权限状态为使用中时可发起离职注销，申请注销字段会更新为离职。
  - 姓名（name）：text，必填
  - 员工编号（employee_no）：text，必填
  - 卡号（card_no）：text，必填
  - 权限状态（permission_status）：enum，必填
  - 申请注销（cancellation_application）：enum，选填
- **门禁卡管理员**（card_admin）
  - 描述：负责门禁卡线下回收的管理员信息，按园区或OCG区分，包含管理员姓名与工号，如园区李媛/WS04462、OCG徐敏/IT006877。
  - 所属区域（region）：enum，必填
  - 管理员姓名（admin_name）：text，必填
  - 管理员工号（admin_no）：text，必填

### 接口设计

- **完成领签**
  - PATCH /api/access-card-applications/claim
  - 契约 `access_card_application_contract`，端点 `access_card_application_contract.completeClaim`
  - 描述：将已勾选的门禁卡申请明细的领签状态由「待领签」更新为「已领签」，并把签收结果同步回飞码端门禁卡管理系统，返回更新后的明细。
- **获取本人待领签申请明细**
  - GET /api/access-card-applications
  - 契约 `access_card_application_contract`，端点 `access_card_application_contract.listAccessCardApplications`
  - 描述：按扫码人ID查询本人名下领签状态为「待领签」的门禁卡申请明细列表，支持分页，供门禁卡领用页面表格展示姓名、员工编号、卡号、领签状态。
- **发起离职注销申请**
  - PATCH /api/access-cards/cancellation
  - 契约 `access_card_contract`，端点 `access_card_contract.applyCancellation`
  - 描述：为本人名下权限状态为「使用中」的门禁卡发起离职注销申请，将对应卡片的申请注销字段更新为「离职」，并把注销申请数据同步至飞码端以触发其现有注销流程，返回更新后的门禁卡信息。
- **获取本人使用中门禁卡列表**
  - GET /api/access-cards
  - 契约 `access_card_contract`，端点 `access_card_contract.listAccessCards`
  - 描述：按扫码人ID查询本人名下权限状态为「使用中」的门禁卡列表，支持分页，供门禁卡归还页面表格展示姓名、员工编号、卡号、权限状态。
- **获取门禁卡管理员列表**
  - GET /api/card-admins
  - 契约 `card_admin_contract`，端点 `card_admin_contract.listCardAdmins`
  - 描述：读取门禁卡管理员信息列表，包含所属区域、管理员姓名和管理员工号，用于已完成界面展示园区李媛/WS04462与OCG徐敏/IT006877的交卡联系人信息。
- **获取问候语**
  - GET /api/greetings
  - 契约 `greeting_contract`，端点 `greeting_contract.getGreeting`
  - 描述：返回应用展示的问候字符串，当前内容为「早上好！」，供欢迎页主体区域展示，无需任何请求参数即可读取。

  - 描述：员工查看本人名下待领签的门禁卡申请明细并完成领用签收。页面自上而下为标题「门禁卡领用」、说明文案「所有字段信息直接从扫码获取，并实时同步到飞码」、可翻页的申请明细列表（字段：姓名、员工编号、卡号、领签状态）、操作区（【完成领签】按钮、【返回首页】按钮）及底部功能图标区；支持单条勾选与一键全选，仅展示本人名下【待领签】的明细。
  - 目标：让员工在手机上核对自己名下待领签的门禁卡申请明细，通过勾选并完成领签，一步完成签收并让状态同步回飞码。
- **门禁卡归还页面**（card_return，路径：/page/access_card/return）
  - 描述：员工查看本人名下状态为「使用中」的门禁卡并发起离职注销申请（页面标题为「门禁卡退还」）。页面自上而下为标题区、说明文案「所有字段信息直接从扫码获取，并实时同步到飞码」、可翻页的门禁卡信息列表（字段：姓名、员工编号、卡号、权限状态）、操作区（【离职注销】按钮、【返回首页】按钮）及底部功能图标区；点击【离职注销】提交注销申请后返回门禁卡管理主页面。
  - 目标：让员工核对自己名下使用中的门禁卡，一键发起离职注销申请，申请提交后回到门禁卡管理主页面，并知晓需线下将实体卡交还门禁卡管理员。
- **已完成界面**（cancel_completed，路径：/page/access_card/cancel_completed）
  - 描述：离职注销申请提交成功后的确认提示页。居中展示标题「您已完成注销申请！」与说明文案「请把实体卡交给门禁卡管理员」，列出门禁卡管理员信息（园区：李媛/WS04462；OCG：徐敏/IT006877），并提供蓝色背景的【返回首页】按钮及底部功能图标区。
  - 目标：明确告知员工注销申请已提交成功，并指引其将实体卡线下交还给对应区域的门禁卡管理员。

**业务流程**：
- 查看欢迎问候
  - 使用人员打开应用首页，前端调用接口获取问候字符串并展示。
  - 步骤：使用人员打开应用首页
  - 步骤：前端请求后端问候接口
  - 步骤：接口返回字符串「早上好！」
  - 步骤：前端在页面主体区域展示该字符串
- 门禁卡领用签收
  - 员工通过招乎APP扫码进入小程序，查看本人名下待签收的门禁卡申请明细并完成领用签收，签收状态实时回传飞码。
  - 步骤：员工使用招乎APP扫描二维码进入小程序
  - 步骤：MP识别扫码人ID
  - 步骤：通过扫码ID与领签人匹配，识别本人名下【待签收】的申请数据明细
  - 步骤：手机端在门禁卡领用页面展示明细列表
  - 步骤：员工单条勾选或一键全选待领签明细
  - 步骤：点击【完成领签】，回填每条申请的【领签状态】为【已领签】
  - 步骤：签收状态数据传回飞码
- 离职注销申请
  - 员工查看本人名下使用中的门禁卡并发起离职注销申请，数据回传飞码触发注销流程，提交后返回门禁卡管理主页面，由员工线下将实体卡交还门禁卡管理员。
  - 步骤：员工使用招乎APP扫描二维码进入小程序
  - 步骤：识别扫码人ID，筛选本人名下【权限状态】为【使用中】的卡片信息展示
  - 步骤：点击【离职注销】按钮
  - 步骤：将【申请注销】字段更新为“离职”
  - 步骤：数据传回飞码，并在飞码发起现有注销流程
  - 步骤：提交成功后返回门禁卡管理主页面

### 技术计划

- 前端架构：基于单页应用生成页面、路由和 API 客户端。
- 后端架构：后端技术栈固定为 Java8 + Springboot，提供真实 HTTP API、资源接口和业务契约实现。
- 数据层：数据库固定使用 MySQL8，缓存固定使用 Redis。

**实体**：
- **问候语**（greeting）
  - 描述：应用向前端返回并展示的问候字符串，核心内容为「早上好！」，由后端接口统一提供。
  - 问候语内容（content）：text，必填
- **门禁卡申请明细**（access_card_application）
  - 描述：员工名下的一条门禁卡领用申请明细，包含姓名、员工编号、卡号、领签状态以及领签人身份标识（扫码人ID），领签状态在待领签与已领签之间流转。
  - 姓名（name）：text，必填
  - 员工编号（employee_no）：text，必填
  - 卡号（card_no）：text，必填
  - 领签状态（claim_status）：enum，必填
  - 领签人身份标识（claimer_id）：text，必填
- **门禁卡**（access_card）
  - 描述：员工名下的一张门禁卡信息，包含姓名、员工编号、卡号、权限状态和申请注销字段；权限状态为使用中时可发起离职注销，申请注销字段会更新为离职。
  - 姓名（name）：text，必填
  - 员工编号（employee_no）：text，必填
  - 卡号（card_no）：text，必填
  - 权限状态（permission_status）：enum，必填
  - 申请注销（cancellation_application）：enum，选填
- **门禁卡管理员**（card_admin）
  - 描述：负责门禁卡线下回收的管理员信息，按园区或OCG区分，包含管理员姓名与工号，如园区李媛/WS04462、OCG徐敏/IT006877。
  - 所属区域（region）：enum，必填
  - 管理员姓名（admin_name）：text，必填
  - 管理员工号（admin_no）：text，必填

### 接口设计

- **完成领签**
  - PATCH /api/access-card-applications/claim
  - 契约 `access_card_application_contract`，端点 `access_card_application_contract.completeClaim`
  - 描述：将已勾选的门禁卡申请明细的领签状态由「待领签」更新为「已领签」，并把签收结果同步回飞码端门禁卡管理系统，返回更新后的明细。
- **获取本人待领签申请明细**
  - GET /api/access-card-applications
  - 契约 `access_card_application_contract`，端点 `access_card_application_contract.listAccessCardApplications`
  - 描述：按扫码人ID查询本人名下领签状态为「待领签」的门禁卡申请明细列表，支持分页，供门禁卡领用页面表格展示姓名、员工编号、卡号、领签状态。
- **发起离职注销申请**
  - PATCH /api/access-cards/cancellation
  - 契约 `access_card_contract`，端点 `access_card_contract.applyCancellation`
  - 描述：为本人名下权限状态为「使用中」的门禁卡发起离职注销申请，将对应卡片的申请注销字段更新为「离职」，并把注销申请数据同步至飞码端以触发其现有注销流程，返回更新后的门禁卡信息。
- **获取本人使用中门禁卡列表**
  - GET /api/access-cards
  - 契约 `access_card_contract`，端点 `access_card_contract.listAccessCards`
  - 描述：按扫码人ID查询本人名下权限状态为「使用中」的门禁卡列表，支持分页，供门禁卡归还页面表格展示姓名、员工编号、卡号、权限状态。
- **获取门禁卡管理员列表**
  - GET /api/card-admins
  - 契约 `card_admin_contract`，端点 `card_admin_contract.listCardAdmins`
  - 描述：读取门禁卡管理员信息列表，包含所属区域、管理员姓名和管理员工号，用于已完成界面展示园区李媛/WS04462与OCG徐敏/IT006877的交卡联系人信息。
- **获取问候语**
  - GET /api/greetings
  - 契约 `greeting_contract`，端点 `greeting_contract.getGreeting`
  - 描述：返回应用展示的问候字符串，当前内容为「早上好！」，供欢迎页主体区域展示，无需任何请求参数即可读取。
