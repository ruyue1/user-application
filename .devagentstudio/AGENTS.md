## 分支 v1_0（2026-11-24 08:33:40 UTC）

**变更说明**：Z000000-0000 #comment chore: 新增人员明细页面，以列表形式展示人员信息供所有用户浏览，并完成配套的数据读取与接口支持。

### 应用现状

- 应用名称：人员明细
- 应用场景：人员明细列表页，所有人都可查看人员的明细列表，不能删改查人员信息；
- 目标终端：PC
- 导航布局：布局=side, 页头=启用, 页脚=禁用
- 主题色：#6b3cf0
- 数据源类型：database
- 认证：不启用
- 权限控制：不启用

### 需求规格

> 「人员明细」是一个面向 PC 端的只读人员信息查看应用，采用侧边导航布局，启用页头、禁用页脚，数据来源于数据库。应用仅包含一个人员明细列表页并作为进入应用后的落地页。所有用户均可查看人员的明细列表，但不能对人员信息进行删除、修改或查询（筛选）操作。应用不启用认证，也不涉及权限控制。

**用户角色**：
- 人员查看者：所有进入应用的用户，均可查看人员明细列表，但不能删除、修改或查询人员信息。

**功能模块**：
- 人员明细查看（must）：提供人员明细列表的只读查看能力，管理并展示数据库中的人员明细信息。支持浏览人员明细列表；不支持删除、修改或查询（筛选）人员信息。该模块仅包含一个列表页面作为应用落地页，未提供任何首页或仪表盘页面。所有用户均可查看，无权限限制。

### 产品计划

**页面**：
- **人员明细**（personnel_detail_list，路径：/page/detail）
  - 描述：人员明细列表页，也是应用进入后的唯一落地页。以列表形式展示数据库中的人员明细信息，供所有用户查看。用户仅可浏览列表，不能删除、修改或查询（筛选）人员信息。页面采用侧边导航布局，页头启用、页脚禁用，导航菜单标题为「人员明细」。
  - 目标：为所有进入应用的用户提供人员明细信息的只读列表浏览能力，使用户能够集中查看数据库中的人员明细，同时确保不提供任何删除、修改或查询（筛选）人员信息的操作。

**业务流程**：
- 浏览人员明细列表
  - 用户进入应用后查看人员明细列表的只读浏览流程，不涉及任何数据修改操作。
  - 步骤：用户进入应用，应用默认落地到人员明细列表页。
  - 步骤：系统以列表形式展示数据库中的人员明细信息。
  - 步骤：用户浏览人员明细列表内容。
  - 步骤：用户不被提供删除、修改或查询（筛选）人员信息的操作。

### UI 设计稿

- personnel_detail_list

### 技术计划

- 前端架构：基于单页应用生成页面、路由和 API 客户端。
- 后端架构：后端技术栈固定为 Java8 + Springboot，提供真实 HTTP API、资源接口和业务契约实现。
- 数据层：数据库固定使用 MySQL8，缓存固定使用 Redis。

**实体**：
- **人员**（personnel）
  - 描述：表示系统中的人员明细记录，用于在只读列表中集中查看人员信息。
  - 记录ID（唯一标识）（id）：number，必填
  - 姓名（name）：text，必填
  - 性别（gender）：enum，选填
  - 出生日期（birth_date）：date，选填
  - 联系电话（phone）：text，选填
  - 电子邮箱（email）：text，选填
  - 所属部门（department）：text，选填
  - 职位（position）：text，选填
  - 入职日期（hire_date）：date，选填
  - 备注（remark）：long_text，选填

### 接口设计

- **分页查询人员明细列表**
  - GET /api/personnel
  - 契约 `personnel_contract`，端点 `personnel_contract.listPersonnel`
  - 描述：分页读取人员明细记录，供只读列表集中浏览人员信息，支持分页参数 current 和 pageSize。

### 数据源

- **studio**（类型：database）
