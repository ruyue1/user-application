# 人员明细需求 Spec

## 应用信息

- 名称：人员明细
- 目标：
- 确认需求摘要：「人员明细」是一款面向 PC 端的人员明细信息查看应用。应用以侧边导航布局呈现（页头启用、页脚禁用），提供人员明细列表页，任何使用者均可查看人员的基本明细信息，但不得新增、删除或修改人员信息。列表采用普通分页方式展示数据，数据来源于数据库，应用不启用登录认证，也不涉及权限控制。此外，应用在侧边导航中新增独立的问候页，页面调用问候接口获取接口固定返回的字符串「晚上好！」并直接展示，该问候语内容固定、不随时间变化，页面同样仅提供只读展示能力。
- 状态：已确认
- 版本：1.0

## 业务参与者（非授权角色）

- `personnel_viewer` 人员信息查看者：查看人员明细列表及人员基本明细信息的业务参与者，仅具备查看能力，不得删除、修改或查询检索以外的变更人员信息操作。

## 权限需求

- 不涉及应用级资源授权。

## 认证需求

- 不涉及登录认证基础能力。

## 功能模块

- `personnel_detail_management` 人员明细管理：承载人员明细信息的展示能力。维护人员明细列表的展示，包括人员基本明细信息的呈现。仅支持查看操作，不提供新增、删除、修改人员信息的能力。列表采用普通分页方式逐页浏览，不提供额外的检索、筛选或导出能力。该只读约束对本应用所有涉及人员明细的页面统一生效。（must）
- `greeting_display` 问候展示：承载问候语的展示能力。提供独立的问候页，页面调用问候接口 GET /greeting 获取接口固定返回的字符串「晚上好！」，并将该字符串直接展示在页面上。问候语内容固定，不随时间或其他参数变化。该模块为只读展示能力，不提供任何数据新增、删除、修改入口，人员明细管理模块的只读约束不受影响。（must）

## 页面清单

- `/page/pers-detail` 人员明细列表：人员明细列表页为本应用首页，位于启用页头的侧边导航布局中。页面以表格形式展示人员的明细信息，支持以普通分页方式逐页浏览人员数据。所有使用者均可查看人员明细列表，页面不提供人员信息的新增、删除、修改入口，也不提供除分页浏览外的其他数据处理操作。
- `/page/greeting` 问候：问候页为侧边导航中新增的独立页面，位于启用页头的侧边导航布局中。页面加载时调用问候接口 GET /greeting，接口固定返回字符串「晚上好！」，页面将该字符串直接展示给使用者。页面不提供任何新增、删除、修改等数据处理操作，也不涉及人员明细信息。原人员明细列表页保持不变。

## 业务流程

- 人员明细查看流程：使用者浏览人员明细信息的只读流程，贯穿列表页，遵循人员明细管理模块的只读约束。；使用者进入人员明细应用，通过侧边导航进入人员明细列表页 → 系统以表格形式展示人员的明细信息，并按普通分页方式分页呈现 → 使用者通过分页控件切换页面，逐页查看人员明细信息 → 使用者查看人员明细信息，系统不提供新增、删除或修改人员信息的操作入口
