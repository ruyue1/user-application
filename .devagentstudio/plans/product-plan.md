# 成都中心门禁卡管理系统产品规划

- 摘要：面向成都中心全体员工的门禁卡管理移动端小程序，员工通过扫码身份识别后可在线完成本人名下门禁卡的领用签收、离职注销申请，并查看注销完成确认信息；出差卡借用与归还功能暂以占位按钮保留，不提供实际功能；所有数据与飞码端门禁卡管理系统实时同步，管理审批流程由飞码端负责。同时包含早安问候页面，通过接口获取并展示字符串「早上好！」。
- 状态：confirmed
- 版本：0.1.0

## 页面与用户操作

### 主页面

- 页面 ID：`main`
- 路由：`/page/main`
- 页面目标：作为小程序入口，向员工集中呈现门禁卡领用与归还两项可用功能入口，并明确出差卡相关功能暂未开放。
- 页面跳转：card_claim、card_return

业务信息：
- `page_title` 页面标题：居中展示的小程序标题「成都中心门禁卡管理系统」，用于确认当前所处系统。
- `function_buttons` 功能按钮组：纵向排列的四个矩形按钮：门禁卡领用、门禁卡归还、出差卡借用、出差卡归还；其中出差卡借用与出差卡归还为禁用占位状态。
- `bottom_decoration` 底部装饰图形：页面底部边缘的高楼大厦、柱状图等装饰性图形，不承载业务信息。

核心操作：
- `goto_claim` 门禁卡领用：员工点击门禁卡领用按钮，进入领用签收页面。；页面跳转；预期结果 跳转至门禁卡领用页面，展示本人名下待领签的门禁卡申请明细。；目标页面 `card_claim`
- `goto_return` 门禁卡归还：员工点击门禁卡归还按钮，进入归还（离职注销）页面。；页面跳转；预期结果 跳转至门禁卡归还页面，展示本人名下使用中的门禁卡信息。；目标页面 `card_return`

产品验收标准：
- 页面目标和核心操作可以由目标角色完成。
### 门禁卡领用页面

- 页面 ID：`card_claim`
- 路由：`/page/card/claim`
- 页面目标：让员工核对本人名下待领签的门禁卡申请明细，并以勾选方式一次性完成领用签收，使签收状态同步至飞码端。
- 页面跳转：main

业务信息：
- `page_title` 页面标题：页面顶部显示标题「门禁卡领用」。
- `claim_notice` 说明文案：提示所有字段信息直接从扫码获取，并实时同步到飞码。
- `claim_detail_table` 申请明细表格：展示本人名下待领签的门禁卡申请明细，字段为姓名、员工编号、卡号、领签状态，行数据可勾选，列表支持翻页。
- `bottom_icons` 底部图标区：页面底部展示四个装饰性功能图标。

核心操作：
- `select_row` 勾选明细行：员工单条勾选或取消勾选申请明细行，用于指定需要签收的明细。；界面行为；预期结果 被勾选的明细行呈现选中状态，取消勾选后恢复未选中状态。
- `select_all` 一键全选：员工点击全选，一次性选中当前列表中的待领签申请明细。；界面行为；预期结果 当前列表内所有待领签明细行同时呈现选中状态，再次操作可取消全选。
- `complete_claim` 完成领签：员工将已勾选（或全选）的申请明细提交领用签收。；业务结果；预期结果 已勾选明细的领签状态由「待领签」更新为「已领签」，更新结果实时同步至飞码，页面给出签收成功反馈。
- `back_home` 返回首页：员工点击返回首页按钮，回到主页面。；页面跳转；预期结果 返回主页面，展示四个功能入口按钮。；目标页面 `main`

产品验收标准：
- 页面目标和核心操作可以由目标角色完成。
### 门禁卡归还页面

- 页面 ID：`card_return`
- 路由：`/page/card/return`
- 页面目标：让员工查看本人名下使用中的门禁卡并发起离职注销申请，由飞码端承接后续注销流程，同时明确线下归还实体卡事项。
- 页面跳转：deactivation_done、main

业务信息：
- `page_title` 页面标题：页面顶部显示标题「门禁卡退还」。
- `return_notice` 说明文案：提示所有字段信息直接从扫码获取，并实时同步到飞码。
- `card_info_table` 门禁卡信息表格：展示本人名下权限状态为使用中的门禁卡信息，字段为姓名、员工编号、卡号、权限状态，支持翻页。
- `bottom_icons` 底部图标区：页面底部展示四个装饰性功能图标。

核心操作：
- `apply_deactivation` 离职注销：员工对本人名下使用中的门禁卡发起离职注销申请。；组合行为；预期结果 门禁卡的申请注销字段更新为离职并同步至飞码，飞码发起现有注销流程，随后进入已完成界面。；步骤 `submit_deactivation` 本人名下使用中的门禁卡申请注销字段更新为离职，数据同步至飞码并由飞码触发注销流程。 → `goto_done` 跳转至已完成界面，提示员工将实体卡交给门禁卡管理员。
- `back_home` 返回首页：员工点击返回首页按钮，回到主页面。；页面跳转；预期结果 返回主页面，展示四个功能入口按钮。；目标页面 `main`

产品验收标准：
- 页面目标和核心操作可以由目标角色完成。
### 已完成界面

- 页面 ID：`deactivation_done`
- 路由：`/page/card/deactivation-done`
- 页面目标：向员工确认离职注销申请已提交成功，告知线下交还实体卡的要求及对应区域的门禁卡管理员联系方式。
- 页面跳转：main

业务信息：
- `done_title` 确认标题：页面居中显示的标题「您已完成注销申请！」，用于确认注销申请已提交。
- `return_notice` 线下归还提示：提示员工将实体卡交给门禁卡管理员。
- `admin_info` 门禁卡管理员信息：展示对应区域的管理员信息：园区为李媛/WS04462，OCG为徐敏/IT006877。
- `bottom_icons` 底部图标区：页面底部展示四个装饰性功能图标。

核心操作：
- `back_home` 返回首页：员工点击蓝底返回首页按钮，回到主页面。；页面跳转；预期结果 返回主页面，展示四个功能入口按钮。；目标页面 `main`

产品验收标准：
- 页面目标和核心操作可以由目标角色完成。
### 早安问候页面

- 页面 ID：`morning_greeting`
- 路由：`/page/morning-greeting`
- 页面目标：在用户进入早安问候页面时自动获取并清晰展示问候语「早上好！」。
- 页面跳转：无

业务信息：
- `morning_greeting_text` 早安问候语：展示从服务端获取的问候字符串「早上好！」。

核心操作：
- 无

产品验收标准：
- 用户访问早安问候页面（/page/morning-greeting）时，页面自动获取问候内容并清晰展示字符串「早上好！」。

## 产品级验收标准

- 员工进入主页面可看到「成都中心门禁卡管理系统」标题及门禁卡领用、门禁卡归还、出差卡借用、出差卡归还四个按钮，其中出差卡借用与出差卡归还保持禁用占位状态。
- 员工仅能查看和操作本人名下的门禁卡申请明细与使用中门禁卡记录。
- 在门禁卡领用流程中，员工可单选或全选本人「待领签」的申请明细并完成领签，完成后状态更新为「已领签」并同步至飞码端。
- 在门禁卡离职注销流程中，员工可查看本人「使用中」的门禁卡并发起离职注销申请，提交后数据同步至飞码端并跳转至已完成界面，准确展示线下交还实体卡提示及园区（李媛/WS04462）、OCG（徐敏/IT006877）管理员信息。
- 门禁卡领用页面、门禁卡归还页面及已完成界面均支持点击「返回首页」回到主页面。
- 用户访问早安问候页面时，页面从后端获取并准确展示字符串「早上好！」。
