# 成都中心门禁卡管理系统产品规划

- 摘要：面向成都中心门禁卡管理的移动端（招乎APP扫码进入MP小程序）应用，同时在PC端保留问候展示能力。员工通过扫码识别本人身份，在移动端查看本人名下待领签的门禁卡申请明细并完成领用签收，查看本人名下使用中的门禁卡并发起离职注销申请；出差卡借用/归还仅作占位按钮。签收状态、注销申请等数据实时同步至飞码端门禁卡管理系统，审批与流程发起由飞码端完成，小程序不涉及管理权限。员工的领用签收与离职注销申请均在对应页面内直接提交完成，不再提供注销完成提示界面。应用整体采用简洁扁平化的蓝色调风格。
- 状态：confirmed
- 版本：0.1.0

## 页面与用户操作

### 欢迎页

- 页面 ID：`home`
- 路由：`/page/home`
- 页面目标：让使用人员打开应用后，在页面主体区域直接看到接口返回的问候语「早上好！」，无需任何额外操作即可确认应用运行正常。
- 页面跳转：无

业务信息：
- `greeting_text` 问候语：后端接口返回并展示在页面主体区域的字符串内容，即「早上好！」。
- `greeting_context` 页面主题说明：帮助使用人员理解该问候语的来源与含义的简要说明，例如表明这是应用的欢迎问候。

核心操作：
- 无

产品验收标准：
- 页面目标和核心操作可以由目标角色完成。
### 门禁卡管理主页面

- 页面 ID：`access_card_main`
- 路由：`/page/access_card/main`
- 页面目标：作为扫码进入后的首页与功能入口，让员工一眼看清可用的门禁卡功能，并能一键进入领用签收或归还注销流程。
- 页面跳转：card_claim、card_return

业务信息：
- `app_title` 系统标题：顶部居中展示的标题「成都中心门禁卡管理系统」，表明当前应用身份。
- `function_entries` 功能入口按钮：纵向排列的四个矩形按钮：门禁卡领用、门禁卡归还、出差卡借用、出差卡归还，代表员工可办理的业务入口。
- `placeholder_entries` 占位功能说明：出差卡借用、出差卡归还两个按钮带禁用标识，向员工传达该功能暂不提供。
- `decoration` 底部装饰图形：页面底部边缘的高楼大厦、柱状图等抽象装饰图形，仅起视觉点缀作用。

核心操作：
- `go_claim` 进入门禁卡领用：员工点击【门禁卡领用】按钮，进入门禁卡领用页面办理领用签收。；页面跳转；预期结果 跳转至门禁卡领用页面，并展示本人名下待领签的门禁卡申请明细。；目标页面 `card_claim`
- `go_return` 进入门禁卡归还：员工点击【门禁卡归还】按钮，进入门禁卡归还页面办理离职注销申请。；页面跳转；预期结果 跳转至门禁卡归还页面，并展示本人名下使用中的门禁卡信息。；目标页面 `card_return`
- `tap_trip_borrow` 点击出差卡借用：员工点击暂未开放的【出差卡借用】占位按钮。；界面行为；预期结果 按钮以禁用样式呈现且不进入任何业务页面，员工可感知该功能暂不提供。
- `tap_trip_return` 点击出差卡归还：员工点击暂未开放的【出差卡归还】占位按钮。；界面行为；预期结果 按钮以禁用样式呈现且不进入任何业务页面，员工可感知该功能暂不提供。

### 门禁卡领用页面

- 页面 ID：`card_claim`
- 路由：`/page/access_card/claim`
- 页面目标：让员工在手机上核对自己名下待领签的门禁卡申请明细，通过勾选并完成领签，一步完成签收并让状态同步回飞码。
- 页面跳转：access_card_main

业务信息：
- `page_title` 页面标题：页面顶部标题「门禁卡领用」，标明当前办理的业务。
- `sync_note` 说明文案：「所有字段信息直接从扫码获取，并实时同步到飞码」，向员工说明数据来源与同步方式。
- `claim_list` 待领签申请明细列表：本人名下待领签的门禁卡申请明细，包含姓名、员工编号、卡号、领签状态四个字段，数据量较大时分页展示。
- `selection_state` 勾选状态：每条明细可被勾选或取消勾选，反映员工即将签收的申请范围。
- `bottom_icons` 底部功能图标：页面底部四个代表不同功能或操作的图标。

核心操作：
- `toggle_row` 勾选或取消勾选明细：员工点击单条申请明细前的勾选框，选择或不选择该条待领签明细。；界面行为；预期结果 该条明细的勾选状态在已勾选与未勾选之间切换，并反映在准备签收的明细范围中。
- `select_all` 一键全选：员工点击全选控件，一次性勾选全部待领签明细。；界面行为；预期结果 全部待领签明细均被勾选，全选控件随之呈现已选中状态。
- `complete_claim` 完成领签：员工点击【完成领签】，将已勾选明细的领签状态更新为已领签并同步回飞码。；业务结果；预期结果 已勾选明细的领签状态更新为「已领签」，签收结果同步至飞码端门禁卡管理系统，页面同步反映最新状态。
- `back_home` 返回首页：员工点击【返回首页】退出当前页面，回到门禁卡管理主页面。；页面跳转；预期结果 回到门禁卡管理主页面。；目标页面 `access_card_main`

产品验收标准：
- 页面目标和核心操作可以由目标角色完成。
### 门禁卡归还页面

- 页面 ID：`card_return`
- 路由：`/page/access_card/return`
- 页面目标：让员工核对自己名下使用中的门禁卡，在本页面一键发起离职注销申请，申请提交后直接返回首页，后续审批与流程由飞码端完成。
- 页面跳转：access_card_main

业务信息：
- `page_title` 页面标题：页面顶部展示的标题「门禁卡退还」。
- `sync_notice` 同步说明文案：说明文案「所有字段信息直接从扫码获取，并实时同步到飞码」，告知员工数据来源与回传方式。
- `card_list` 使用中门禁卡列表：仅展示本人名下权限状态为【使用中】的门禁卡，逐条包含姓名、员工编号、卡号、权限状态四项字段。
- `pagination` 列表翻页：门禁卡列表支持翻页浏览，便于员工核对多条卡片记录。
- `cancellation_field` 申请注销标记：卡片上体现的申请注销字段，提交离职注销后该字段为「离职」。

核心操作：
- `apply_cancellation` 离职注销：员工发起本人名下使用中门禁卡的离职注销申请，将申请注销字段置为「离职」并同步回飞码以触发其注销流程。；组合行为；预期结果 离职注销申请提交成功后页面自动返回首页，飞码端收到注销申请并发起注销流程。；步骤 `submit_cancellation` 本人名下使用中的门禁卡申请注销字段更新为「离职」，注销申请数据同步至飞码端。 → `return_to_home` 页面返回门禁卡管理主页面。
- `back_home` 返回首页：员工点击【返回首页】，回到门禁卡管理主页面。；页面跳转；预期结果 返回门禁卡管理主页面。；目标页面 `access_card_main`

产品验收标准：
- 页面自上而下依次展示标题「门禁卡退还」、说明文案「所有字段信息直接从扫码获取，并实时同步到飞码」、门禁卡列表、操作区与底部功能图标区。
- 列表仅展示本人名下权限状态为【使用中】的门禁卡，每条展示姓名、员工编号、卡号、权限状态。
- 门禁卡列表可翻页浏览，翻页后展示对应页的卡片数据。
- 点击【离职注销】并确认后，注销申请提交成功，页面直接返回门禁卡管理主页面。
- 申请提交后不再展示注销完成提示界面，员工无需额外确认即可回到首页。
- 点击【返回首页】回到门禁卡管理主页面。

核心操作：

## 产品级验收标准

- 员工通过招乎APP扫码进入小程序后，可通过门禁卡管理主页面进入门禁卡领用与门禁卡归还功能。
- 门禁卡领用页面仅展示本人名下【待领签】明细，员工可通过单条勾选或一键全选后点击【完成领签】完成签收，签收结果同步回飞码。
- 门禁卡归还页面仅展示本人名下【使用中】的卡片，员工点击【离职注销】后申请提交成功并直接返回首页，全程不出现注销完成提示界面。
- 出差卡借用与出差卡归还按钮在主页面以占位形式呈现，点击不产生业务结果。
- 欢迎页可直接展示接口返回的问候语「早上好！」，满足PC前端的问候展示能力。
- 各页面均为简洁扁平化的蓝色调风格，且提供【返回首页】回到门户主页面的入口。
